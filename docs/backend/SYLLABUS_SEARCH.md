# 강의계획서 검색과 원문 제공

`backend/app/syllabus.py`는 과목명/학수번호로 문서를 찾은 다음 학년도·학기·분반을
정확히 비교한다. 질문의 평가·교재·교수·선수과목·주차별 계획 표현은 문서 조회의
AND 조건으로 사용하지 않고, 선택된 강좌 내부 청크의 우선순위와 근거 구간을 고르는 데 사용한다.
JSON과 SSE 응답 모두 같은 경로를 사용한다.

학기·분반 조건으로 강좌가 하나로 정해지지 않으면 최대 12개 후보의 학기·학수번호·분반·
학과·교수를 구분해서 보여주고 선택을 요청한다. 국문·영문·공학인증은 동일 강좌의
문서 유형으로 묶고 국문을 우선 사용한다. 이전 사용자 질문이 있는 선택 응답은 해당
과목과 질문 목적을 이어받는다. 일치하는 강좌가 없으면 다른 과목으로 대체하지 않는다.
후보 수가 상한을 넘으면 일부 결과만 보고 한 강좌로 확정하지 않는다.

이력 복원 전 DB도 파일명과 원본 경로에서 과목·학기·분반을 읽어 검색할 수 있다.
학과·교수는 복원한 메타데이터를 우선 사용하고, 구버전에는 첫 청크에서 확인되는
값만 보충한다. 확인되지 않은 값은 미확인으로 표시한다.

## 교수별 강좌 목록 조회

“유승호 교수님이 진행하는 강의명을 알려줘”처럼 교수별 목록을 요청하면
`pknu_syllabus_sources`의 활성 문서 메타데이터를 직접 조회한다. 교수명(`staff_name`),
학년도(`year`), 학기(`term`), 과정(`level`)을 각각 비교하며 일반 벡터 검색이나 Excel
본문에서 교수명 주변의 과목을 가져오지 않는다. “대학원”은 대학원 과정 전체를,
“산업대학원” 등의 명칭은 해당 과정을 가리킨다.

학기·과정이 생략되어 여러 후보가 있으면 학년도·학기·과정 목록을 보여주고 선택을
요청한다. “2026-2학기 학부만”, “전체 강의명만 알려줘” 같은 후속 질문은 이전
사용자 질문의 교수와 조건을 이어받는다. 이전 답변의 과목명은 조회 조건에 사용하지
않는다. “전체 학기·모든 과정”은 범위를 넓히는 명시적 조건으로 처리한다.

국문·영문·공학인증 보고서는 같은 강좌로 묶고 같은 과목의 여러 분반은 강의명
목록에서 합친다. 목록을 RAG `top_k`로 자르지 않으며, 후보가 조회 상한을 넘으면
조건을 더 지정하도록 요청한다. 결과는 수집된 강의계획서 범위이고 학교 전체의
개설 현황을 보장하지 않는다.

목록 출처는 “공식 강의계획서 조회 — 교수별 강의 목록”으로 제공한다. 같은 조회
화면 URL을 사용하는 각 문서를 한 PDF처럼 표시하지 않으며, 실제 조회한 문서 ID와
강좌·분반은 `source_ids`, `catalogue_offerings`에 보존한다. 개별 PDF 제공은 아래의
별도 설계를 따른다.

## Excel 개설 현황의 행·열 보존

Excel은 원본 시트·행 번호·열 좌표, 다단 열 제목, 빈 셀과 병합 셀을
`structured_table`로 보존한다. 검색용 텍스트에도 열 제목과 같은 행의 과목·교수를
반복한다. 행이 길어 분할되더라도 다음 행과 합치거나 행 사이 overlap을 만들지 않는다.
따라서 한 행 끝의 교수명이 다음 행 과목에 연결되는 문제를 방지한다.

표 구조가 없는 구버전 Excel 청크는 교수와 과목의 관계를 확인하는 근거로 채택하지
않는다. 기존 Excel을 이 구조로 바꾸려면 전처리·벡터화·적재를 다시 수행해야 하며
코드 변경만으로 이미 적재한 청크가 갱신되지는 않는다.

## PDF 표와 기존 데이터 반영

강의계획서 PDF는 `scripts/preprocessing/extractors/syllabus.py`에서 PyMuPDF의
표 경계·셀·행·열 정보를 추출한다. 원본 블록에는 셀 배열과 병합 셀의 좌표를 보존하고,
청크에는 헤더와 행별 셀을 `structured_table`로 전달한다. 빈 셀과 병합 셀을 구분하며
빈 값을 0 또는 선수과목 없음으로 바꾸지 않는다. 표에서 추출한 숫자는 해당 열 이름을
붙여 텍스트에도 보존한다. 같은 표의 행은 청크 크기 내에서 묶되 행 중간을 자르지 않는다.

일반 PDF 추출과 OCR 정책에는 영향을 주지 않는다. 표 선을 인식하지 못하는 PDF나
스캔 문서는 구조가 확인됐다고 가정하지 않으며 원문 검토가 필요하다.

기존 문서의 provenance 복원만으로 이미 적재한 PDF 본문의 표가 복구되지는 않는다.
`table_policy_version=syllabus-tables-v1`이 없는 전처리 문서는 `--changed-only`에서도
재처리 대상이 된다. 원본 PDF를 재다운로드할 필요는 없다.

```powershell
.venv/Scripts/python.exe -m scripts.preprocessing.preprocess_files --input-root files/pknu_syllabus --output-root preprocessed/pknu_syllabus/files --file-ext pdf --changed-only
```

재처리한 문서는 기존 벡터화·적재 절차로 `pknu_syllabus_sources`와
`pknu_syllabus_chunks`에 반영한다. 모델이나 차원을 바꾸지 않는다. 표 청크가 달라지므로
기존 임베딩을 수정된 텍스트에 그대로 붙여서는 안 된다. 재처리 전 전처리 폴더를
백업하고, 적재 시 기존 source identity 및 중복/오래된 청크 정리 정책을 확인한다.

## 조회 화면 링크

응답의 공식 출처 URL은 `irumi.pknu.ac.kr`의 강의계획서 조회 화면이다.
`source_link_kind=syllabus_search_page`로 개별 PDF 직링크와 구분한다.
강좌별로 동일 화면 주소를 쓰더라도 검색의 문서 식별은 `source_id`와 강좌 조건으로
수행하며 URL별 후보 제한으로 서로 다른 분반을 제거하지 않는다.

## 개별 PDF 제공 설계

아래는 별도 도입할 방식이며 현재 파일 다운로드 API를 추가하거나 파일을 공개한 것은 아니다.

1. 검증한 PDF를 비공개 객체 저장소에 `syllabus/<sha256>.pdf`로 저장한다. 같은 원본은
   동일 해시로 재사용하고 source ID에서 저장소 객체·해시·학기·분반을 조회할 수 있게 한다.
2. `GET /syllabus/{source_id}/pdf`는 로그인과 자료 접근 권한을 확인하고, 실제
   `pknu_syllabus_sources`에 연결된 검증 객체만 제공한다. 클라이언트가 파일 경로나
   외부 다운로드 URL을 지정할 수 없게 한다.
3. 서버가 짧은 만료시간(예: 60초)의 서명 URL을 발급하거나 PDF를 스트리밍한다.
   영구 출처에는 source ID 기반 API 주소를 사용하고 임시 서명 URL은 저장하지 않는다.
4. 응답에 `application/pdf`, 안전한 `Content-Disposition` 파일명, 크기 제한,
   접근 감사 기록을 적용한다. 원본 교체는 새 해시로 기록한다.
5. 공개 가능 범위·인증 요구·저작권/학교 제공 정책을 확인한 자료만 등록한다.
   보고서 서버의 세션·rdid·일회성 다운로드 주소를 영구 링크로 노출하지 않는다.
