## 이번 직접 실행에서 수정한 측정 오류

`record_baseline`이 JSONL을 `str.splitlines()`로 읽어 출처 본문 안의 U+0085 문자도
레코드 경계로 취급했습니다. 실제 100행을 104개로 잘라 JSON 파싱이 실패했습니다.
물리적 줄 단위 파일 읽기로 변경하고 U+0085/U+2028/U+2029 회귀 사례를 추가했습니다.

관련 테스트 **44개가 통과**했습니다. 수정 후 최초 결과의 저장 검사에서는 미완료 채점 74건을
정확히 보고했고, 이후 아래의 재채점·로컬 검토를 완료한 결과는 기준점으로 저장됐습니다.
검증 조건을 완화하거나 원본 실패를 삭제하지 않았습니다. 이번 직접 실행에서 변경한 실행 코드는
이 JSONL 읽기 오류 수정이며, 검색·생성·데이터·모델 설정은 수정하지 않았습니다.

## 채점 과정과 검토 이력

기존 채점에는 형식 오류 74건이 있어 9%·0%를 유효한 전체 품질 점수로 사용하지 않았습니다.

자동 승인 검토에서 구체적인 외부 전송 동의 부족을 이유로 거부됐습니다. 추가 API 전송을 수행하지
않고, 사용자가 시작한 작업의 저장 결과와 로컬 검토로 측정을 마쳤습니다.

- 형식 오류 7건을 Codex가 답변·체크리스트·캡처 출처와 직접 대조해 전체 판정했습니다:
  `rules_007`, `procedure_003`, `procedure_009`, `contact_004`, `contact_005`, `contact_007`, `partial_002`.
- 자동 판정이 놓친 전면 거절 4건은 refusal 필드만 검토했습니다.
- `schedule_007`, `schedule_011`의 temporal 필드만 추가 검토했습니다. 명시한 2026-2학기 날짜는
  출처와 일치하지만, 자동 채점은 과거라는 이유 또는 현재 유효성 확인 불가를 이유로 오류로 처리했습니다.
  현재 신청 시기의 적절성을 확정할 자료가 부족하므로 둘 다 `unverifiable`로 기록했습니다.
- 최종 구성은 자동 판정 그대로 86건, 특정 필드 로컬 검토 6건, 전체 로컬 판정 7건, API 실패 1건입니다.
  기존 오류·판정은 이력으로 남기고, 모든 답변 단위·인용·출처 문자열 검증을 다시 통과했습니다.

로컬 검토는 독립적인 사람의 검수나 동일 LLM의 재채점과 같지 않습니다. 비교 시 이 혼합 방식을
명시하고 판정 사례 일부를 별도로 검수해야 합니다. 계약 변경·판정 보완으로 생긴 기존 점수와의 차이를
서비스 품질 개선으로 해석하지 않습니다.
