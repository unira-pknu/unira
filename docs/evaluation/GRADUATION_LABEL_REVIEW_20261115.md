## 두 피드백 질문의 별도 평가 라벨

[`eval/cases/feedback_graduation_20261115.jsonl`](../../eval/cases/feedback_graduation_20261115.jsonl)에
다음 두 문항을 별도 구성했습니다. 기존 100문항 기준점의 분모에 자동으로 합치지 않습니다.

- `feedback_ce_graduation_001`: 일반 졸업요건. 일반 신입생 구간, 공통 성적, 주전공 인증의 적용 범위를 구분합니다.
- `feedback_ce_transfer_001`: 편입생 졸업요건. 교양 예외, 지정 선수과목, 인정학점 포함 졸업 기준,
  성적과 인증 적용 대상을 구분합니다. 모든 편입생에게 66학점이 무조건 인정된다고 단정하지 않습니다.

검수본의 기존 설명은 공개 학점과 성적 기준의 큰 방향은 맞았습니다. 보완한 부분은 적용 대상과
예외입니다. 특히 일반 신입생의 교양 최소학점을 편입생에게 그대로 적용하거나 인정학점을
졸업소요학점에 별도로 더하는 해석을 막습니다.

## 학습·평가 분리와 과거 점수

출처 `https://ce.pknu.ac.kr/ce/2889`는 계속 기본 회귀 평가의 보호 출처입니다.
두 피드백을 `train`으로 승인한 기존 검수본은 라벨을 수정해도 출처 중복 검사에 계속 걸립니다.
이번 작업에서 해당 검수본의 승인·split을 바꾸거나 학습 파일을 생성하지 않았습니다.

별도 평가 파일을 다른 실행에서도 보호하려면 후보 생성·변환 명령에
`--holdout eval/cases/feedback_graduation_20261115.jsonl`을 추가합니다.
별도 파일은 기본 세 개 holdout 파일을 대체하지 않습니다.
이후 추가된 [② 검수·데이터 변환 자동화](FEEDBACK_REVIEW_AUTOMATION.md) 명령은 이 별도 평가 파일도
기본 보호 목록에 포함합니다. 기존 명령의 동작은 위와 같습니다.

2026-11-10 기준점과 저장된 답변·채점 기록은 과거 라벨에 대한 결과로 유지합니다.
라벨 수정만으로 정답률이 개선되었다고 계산하지 않습니다. 새 라벨에 대한 점수는 별도 평가·채점
실행과 새 질문 파일 해시를 사용해 다시 측정해야 합니다.

## 사용자 실행 검증

이번 수정 후 테스트·새 모델 응답 생성·재채점·DB 조회는 실행하지 않았습니다.
문항 형식과 기존 질문 구조의 호환성은 아래 명령으로 확인할 수 있습니다.

```powershell
.\.venv\Scripts\python.exe -m eval.tools.audit_regression_labels
.\.venv\Scripts\python.exe -m eval.tools.audit_regression_labels eval/cases/feedback_graduation_20261115.jsonl
.\.venv\Scripts\python.exe -m pytest eval/tests/test_eval_ask.py eval/tests/test_feedback_training.py
```

실제 모델 응답 수집과 재채점 절차는 [기준점 실행 순서](BASELINES.md#실행-순서)를 따릅니다.
별도 두 문항을 평가할 때는 질문 파일을 `eval/cases/feedback_graduation_20261115.jsonl`로 지정하고
기존 결과와 겹치지 않는 출력 경로를 사용합니다. 평가 계정 토큰은 `eval_ask`가 읽는 프로세스 환경 변수
`ASK_API_TOKEN`으로 준비합니다. 수집 CLI의 `.env` 자동 로딩과는 별도입니다.
